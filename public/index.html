What one session learns, the others know.

Mcelium links your team's Claude sessions. When one session makes a decision, finds something out, or changes something others rely on, the sessions that need it hear about it mid-task. Nobody has to stop and sync.

Share context, not just code.

When several people work with Claude at once, each session builds up context the others never see. Mcelium passes along the parts that matter.

  • Decisions

    What the team settled, so no session keeps working from the old plan.

    "We're going with Postgres." "The free tier is gone."

  • Findings

    Facts one session dug up that another would otherwise spend an hour rediscovering.

    "The partner API caps at 100 requests a minute."

  • Changes

    Edits to things others build on: a spec, a schema, a function, a doc.

    "The onboarding spec now has 3 steps, not 5."

  • Who's on what

    What each teammate's session is working on right now, so two people don't do the same job.

    "Noa's session is already rewriting the FAQ."

How it works

  1. 1

    Connect your sessions

    Each teammate links their Claude session to your team's Mcelium space. It takes one step.

  2. 2

    Mcelium keeps track

    It notes what each session decides, learns and changes, and what each one relies on to do its work.

  3. 3

    Only relevant context arrives

    A session hears about something only when it affects the task in front of it. Everything else stays quiet.

When two sessions disagree, it stops and asks.

Mcelium never quietly overrides a decision. If two sessions head in directions that can't both be true, Claude pauses and shows you both sides.

Code

For code: Git without the push and pull.

In Claude Code, Mcelium reads each edit as code, not text: which functions, types and endpoints you changed, and which ones you rely on. When your agent changes something another agent depends on, that agent adapts mid-task, before anyone sees a broken build.

Dana's agent renames a function. Omer's agent is mid-task, gets the change, and fixes its own calls. Neither of them pulled.

When two code changes collide, it asks.

Mcelium never merges code silently. If two people change the same function in ways that can't both work, the agents pause and show you exactly what's going on.

See who's touching what.

Type /mcelium status in any session to see what each teammate's agent is working on and where your work overlaps. Git stays underneath as the safety net.
